# 量潮课堂工作台（实验室）

「河床架构」的参考实现：把学员旅程（报名 → 问卷 → 进群 → 领任务 → 交付 → 评审 → 出师）还原为**单一系统内的连续流程**。每个状态迁移都是系统内事件，断片之间的衔接不需要任何人在中间缝合。

> 本目录为独立快照样例。生产实现运行于内部环境（含飞书档案镜像、邮件异常通道等业务集成），此处只保留与外部服务无关的架构骨架。

## 核心设计

### 以进度为中枢

旅程时间线常驻左侧作为主干，右侧详情面板永远是「当前节点的动作」——报名表单就是「报名」节点的动作，问卷/进群/领任务/交付是主干上的后续节点。不设并列 Tab：用户在任何状态打开工作台，看到的就是旅程与下一步。

### 状态机即数据

状态枚举、状态到旅程阶段的映射、各节点的动作清单全部是代码里的表（`store.py` 的迁移函数、`workbench.py` 的 `STATUS_STAGE`/`STAGE_DETAIL`）。改流程 = 改表，界面自动跟随。

### 外部系统退位

| 传统做法 | 河床做法 |
|---|---|
| 报名收邮箱，进度靠邮件通知 | 姓名即身份，进度在工作台随时可查 |
| 问卷用外部表单，人工对账回收 | 问卷内嵌，提交即状态迁移（系统内事件） |
| 进群邀请发邮件，退信要人工处理 | 凭证直接展示在面板内（二维码可选资产） |
| 领任务/交作业走邮件 | 工作台内点击与文件上传 |

## 运行

```bash
pip install PySide6
python src/workbench.py
```

无需任何配置。数据落在 `src/data/workbench.db`（SQLite，首次运行自动建库）；入群二维码为可选资产，放入 `src/assets/group-qrcode.png` 即在「进群」节点展示。
